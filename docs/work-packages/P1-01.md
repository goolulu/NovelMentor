## Goal

建立能够独立构建、检查依赖边界并运行身份流程的最小全栈工程：pnpm workspace、React/Vite 前端、Fastify 后端、客户端公开 contracts，以及当前用例真正需要的少量 shared-kernel 类型。依赖方向从第一份代码起受检查，后续领域可在明确边界内增量实现。

通过真实 SQLite、正式迁移和 Identity 的 User／Session 聚合建立个人账号与服务端会话。管理员能安全初始化唯一账号，用户能登录、查询当前身份和退出；账号验证、会话归属、期限、Cookie 与 Origin 检查必须在真实接口上得到验证。

同步建立配置、依赖装配、资源关闭、结构化日志和敏感信息过滤。交付出口是 DDD §15.1 规定的前后端可构建、登录与当前范围资源归属验证通过、密码和密钥不进入日志。此包结束后仍没有书籍或教学能力，也不能宣称 T20 或整个应用已完整验收。

## Scope

### Workspace and boundaries

- 建立 pnpm workspace：`apps/server`、`apps/web`、`packages/contracts`、`packages/shared-kernel`。
- 后端以 Node.js 24 和 TypeScript 为基线；前端采用 React、Vite、TypeScript。在工程建立时验证依赖兼容性、锁定稳定版本并提交锁文件。
- 建立 TypeScript 工程配置和 ESLint 导入规则，检查 domain 的框架隔离、前后端边界及 `public.ts` 跨模块入口；规则对将来的模块同样适用。
- 建立本包所需构建和验证入口。`shared-kernel` 只收纳已有调用点所需的 ID、时钟等无框架类型；不预建完整通用框架。

### Server composition and configuration

- Fastify bootstrap 负责配置加载、数据库／日志／时钟及 Identity 依赖装配、插件和局部 hook 注册、服务启动和资源关闭。
- 配置解析在边界完成，返回类型化结果；验证当前实际依赖的 `APP_ORIGIN`、`DATA_DIR`、数据库目录权限／可写性与迁移结果，不记录配置值或 secret 内容。
- 数据库迁移失败时不得继续启动一个看似可用的身份服务。关闭流程释放 HTTP 与数据库资源，可重新启动同一数据目录。
- 本包不注册 scheduler、parser worker、模型适配器或生产健康检查；DDD 中相关启动校验随其所属工作包落实。P1-01 启动及验收不要求真实模型凭据，也不发起模型请求。

### Public contracts

- 仅建立当前已确认的身份公开 DTO、通用响应／错误及 Zod schema；有限值使用显式字符串枚举，在 domain、持久化和公共表示间映射。
- HTTP 响应按白名单生成，不直接序列化 User、Session 或数据库行；password hash／salt／参数、token hash、会话原值不作为公开用户字段。
- 定稿前处理 [G-01](../implementation-status.md#known-design--implementation-gaps)：用户公开字段、登录失败语义，以及带 password 的登录请求 schema 与 contracts 的边界。本文不代替该契约决定。
- 不建立 Book、ReadingUnit、Tutor、AgentRun 或 Review 的公共类型空壳；不因为 DDD §8 有示例就全部复制进代码。

### Persistence

- 使用 `better-sqlite3` 和 Drizzle；本地 SQLite 文件、单写入连接，所有连接开启外键，写入连接配置 WAL、`synchronous=FULL`、`busy_timeout=5000`。
- 建立可显式执行的正式迁移及迁移记录。本包业务表仅为 DDD §7.5 的 `users`、`sessions`，并遵循 §7.1 的公共 ID、审计字段、时间及 JSON 约定。
- 验证 loginName 和 tokenHash 唯一性、Session 的用户外键、过期时间索引；其他字段及必要约束从原设计派生。不得创建 maintenance_state、request_receipts 或未来业务表。
- 应用端口与仓储实现分离；数据库事务使用同步回调。异步密码计算等外部工作先完成，再进入短事务；提交时重新检查本次写入前提。
- 迁移初始化、重复执行、数据保留、约束与回滚使用真实临时数据库文件验证；不使用 schema push 或 repository mock 代替迁移验收。

### Identity

- `User` 与 `Session` 各自为独立聚合根。Application 定义仓储、密码验证、令牌／时钟等当前必要 ports；infrastructure 实现数据库与密码能力；HTTP 边界不承载领域规则。
- 管理命令创建唯一个人账号。密码仅通过交互输入或挂载 secret 文件取得，不能出现在命令参数、Shell 历史、镜像、仓库或日志；再次初始化不得增加第二账号或无授权重置密码。
- 密码使用 Node.js `crypto.scrypt`：N=32768、r=8、p=1、16 字节独立随机 salt、64 字节输出、maxmem 64 MiB；参数随摘要保存，恒定时间比较（DDD §12.1）。
- 登录创建 32 字节随机令牌，数据库只保存 SHA-256 令牌摘要。Cookie 为 `__Host-novelmentor`，包含 Secure、HttpOnly、SameSite=Strict、Path=/，不设置 Domain。
- Session 绝对有效期七天，lastSeen 更新不能延长绝对期限；退出立即撤销当前会话。测试和日志不能将 Session 的数据库 ID 与 Cookie 令牌混用。
- 登录限速按账号及源地址执行，五分钟内最多十次失败；超限按照 DDD §9.4 返回 429 和 Retry-After。未知账号与错误密码的具体错误契约按 G-01 收敛，二者都不得创建有效 Session。
- 实现 `POST /api/auth/login`、`POST /api/auth/logout`、`GET /api/auth/me`。成功与错误封装遵循 DDD §9；退出成功为 204、无响应体；未登录 me 为 401。
- 身份来自服务端会话，不信任请求体、查询参数或自定义头中的 userId。所有变更请求校验固定 Origin 及适用 Content-Type，关闭跨站 CORS。
- 不开放注册、账号管理、密码找回、OAuth、多租户或额外会话管理 API。

### Web

- 建立 React/Vite 应用、React Router、TanStack Query 及同源 `/api` 访问；只依赖公开 contracts，与服务器实现隔离。
- 仅实现最小登录表单、当前身份展示／受保护入口、退出及登录后原路由恢复。展示可以是身份基础页，不创建书库或阅读器占位业务。
- 会话由浏览器 HttpOnly Cookie 承载，不能在 localStorage／可读 JSON 中保存令牌；刷新通过 me 恢复身份。
- 开发和 E2E 提供可验证的同源 HTTPS 入口，使设计的 Secure／`__Host-` Cookie 生效；证书与测试入口配置属于工程细节，不扩展成生产 Compose 部署，不降低 Cookie 属性来通过测试。

### Observability

- 使用结构化日志，覆盖配置／迁移／启动／退出、初始化账号、登录成功或拒绝、会话过期／撤销、Origin／限速拒绝、持久化失败。
- 按场景记录 event、requestId、已验证的 userId、stage、status、durationMs、errorCode；不为尚未存在的 Book 或 AgentRun 填充虚假字段。
- 对 Authorization、Cookie、Set-Cookie、密码及其摘要、令牌及其摘要、secret 等配置统一过滤。错误不得直接序列化请求、响应或数据库参数；SQL 调试默认关闭。
- 使用合成敏感标记测试成功与失败分支的日志；不需要引入模型或真实密钥来验证过滤规则。

- Runtime、AgentRun、调用预算、任务租约、scheduler、SSE、预取和任务恢复。
- Learning、LearnerProfile、学习项、接触、收藏、求助与学习证据。
- Review、ReviewSession、题目、答案、讲评、提醒及跨域工作流。

## Definition of Done

- P1-01-AC01～AC12 全部满足，12 项 Implementation Tasks 实际完成，G-01 对身份实现的必要契约问题已明确并同步设计。
- 涉及的 INV-07、INV-13 有当前范围的行为证据，没有扩大本包或弱化设计。
- 构建、类型、lint、依赖边界及上表所有适用测试通过；失败／跳过／未运行不能视为通过。
- 正式迁移、公开契约／schema、私有映射、必要日志与注释均随实现提交，敏感值不进入仓库或证据。
- README 有可执行且经过验证的使用命令；implementation-status 记录日期、代码范围、命令、测试路径、结果和剩余全局验收范围，本文状态同步。
- 完成 Design → Task → Code → Test → Design Sync 复核，所需 ADR／canonical design 已按协议更新；只有此时本包才可标记 VERIFIED。

完整应用的模型能力、阅读流程及备份恢复仍按 DDD §14.3 和后续包独立验收。P1-01 VERIFIED 不等于 T01～T25 全部通过。
